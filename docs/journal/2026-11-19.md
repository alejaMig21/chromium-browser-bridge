# 2026-11-19

### 03:00 · decision · Put the project under git, then build in waves

The project had no git history, and the multi-browser spec had ten tickets with blocking edges. After the user agreed, a `.gitignore` kept the private browser profiles (`profile-*/`) and the broker token (`broker.json`) out of history, a baseline commit `48169c7` was made, and every ticket ran in its own worktree. At most two agents ran at once to protect the machine.

**Why it matters:** the work became reviewable and reversible, ten tickets on one integration branch.
**Evidence:** commit `48169c7` · branch `feat/multi-browser` · `.scratch/multi-browser/issues/`

### 03:20 · surprise · A hung test held a port and blocked every later run

A test process left over from one agent kept port 9407, so the same test file failed in every other worktree. The sandbox refused to let the agent kill it by pid, so the user ended that single process by hand. From then on each agent got its own port range and the full test suite was not run while another agent was working.

**Why it matters:** parallel agents sharing fixed test ports is a hidden coupling.
**Evidence:** `bridge.browsers.test.mjs` · ports 9407 and up

### 04:00 · problem · The next call after a browser closed hung for 60 seconds

The live test with two stand-in browsers showed that when one browser went away, the next tool call waited a full minute. The broker closed the socket at once, but Playwright waits out its own connect timeout and hides the close reason, so the agent never saw the message naming the lost browser. The fix reads the broker's list of connected browsers and answers immediately with `<name> disconnected. Still connected: ...`. The same run also showed the test servers leaking temp folders; they now live under the run's own folder.

**Why it matters:** the failure an agent would hit first in real use was found by a real run, not by unit tests.
**Evidence:** commit `c90458c` · `server.mjs` `lostBrowserNote()`

### 04:30 · problem · The code review found a name that stopped working

A browser shown as `chrome-3f9a` (two profiles) lost its suffix when the other profile left, so a reconnect with the stored name matched nothing. The default-browser step also accepted a partial match, so a program called `chromehelper` could have been chosen. Both were fixed test first, together with an over-broad process kill in the live test and a matrix helper that could not work with several browsers connected.

**Why it matters:** two independent reviewers (standards and spec) found real bugs in code whose tests were green.
**Evidence:** commits `c1d1ba0` to `5e131b1` · `platform.mjs` `matchBrowsers`

### 05:00 · milestone · Three real browsers connected at once

After the user reloaded the extension (now 1.1.0) in Chrome, Edge and Vivaldi, all three appeared in the broker within 5 seconds, each named after its own program with its full path. The cross-browser matrix then ran on each one through `browser_attach`, with no broker restart in between: Chrome 10 of 10, Edge 10 of 10, Vivaldi 8 passed and 2 screenshot rows were skipped because its window was covered. Before this, only one browser could be connected and the winner was a race.

**Why it matters:** the user's real setup (Vivaldi, Chrome and Edge open together) now works, which was the whole point of the feature.
**Evidence:** commit `5d74c11` · `.scratch/cross-browser/results.md` · `npm test` 133 of 133, live Chrome 171 and Vivaldi 170 checks
